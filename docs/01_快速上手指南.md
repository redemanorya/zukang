# 01 快速上手指南

> 本章目标：帮助你在最短时间内搭建开发环境、编译烧录固件，并理解 SDK 的基本配置方法。

---

## 1. 开发环境搭建

### 1.1 必需工具

| 工具 | 版本 | 用途 | 下载/安装说明 |
|------|------|------|---------------|
| AndeSight | V3.2.3 | IDE（基于 Eclipse 的 NDS32 开发环境） | 山景官方提供 |
| ACPWorkbench | V5.8.2 | 音效参数配置工具（生成 audio_effect.bin） | 山景官方提供 |
| IAPBurner | V1.8.0 | PC 端烧录工具 | 山景官方提供 |
| MVAssistant | V3.5.3 | 辅助工具 | 山景官方提供 |
| FlashBurner | FSH_V6.6.6 | 烧录器固件 | 山景官方提供 |

### 1.2 安装步骤

1. **安装 AndeSight V3.2.3**
   - 运行安装程序，选择默认路径
   - 安装完成后，确认 `nds32le-elf-gcc` 可在命令行调用

2. **安装 ACPWorkbench V5.8.2**
   - 用于配置音效参数，生成 `audio_effect.bin`
   - 首次使用需导入 SDK 中的音效库

3. **安装 IAPBurner**
   - 用于将编译好的固件烧录到目标板

### 1.3 验证安装

打开命令行，执行以下命令验证工具链：

```bash
nds32le-elf-gcc --version
```

应输出 NDS32 GCC 版本信息（本工程使用的交叉编译前缀为 `nds32le-elf-`，见 `Release/makefile` 中 `CROSS_COMPILE` 定义）。

## 2. 工程导入与编译

### 2.1 导入工程

1. 打开 AndeSight
2. 选择 **File → Import → Existing Projects into Workspace**
3. 选择 SDK 根目录 `d:\MVS_err\workspace\B6_Audio_SDK`
4. 确认工程名 `B6_Audio_SDK` 已导入
5. 检查工程属性：
   - Build Configuration: **Release**
   - Compiler Symbols: 确认 `CFG_APP_CONFIG` 等全局宏已定义

### 2.2 编译工程

1. 右键工程 → **Build Project** (或 `Ctrl+B`)
2. 观察编译日志，确认无 Error
3. 编译产物路径: `Release/output/`，最终烧录文件为 **`main_merge.MVA.bin`**

**编译流程**（2026-09-22 实际编译验证）:
```
makefile.defs（make 解析阶段）
  → GCC 预处理 sys_em_config.h 生成 Release/sys_em.cfg
  → 按 USE_BT_*_LIB 宏选择蓝牙库（当前：libBtStack_noBle.a → libBtStack.a）
→ script.bat (prebuild)
  → update_sag.ps1 按 sys_em.cfg 更新 .sag，nds_ldsag 重新生成 nds32-ae210p.ld
  → ffmpeg 转换提示音 MP3→MP2，MergeAudio2BinNew.exe 生成 all.bin + 提示音头文件
  → copyLibs.exe（当前无 script_copy.ini，空操作）
→ GCC 编译各层源码
  → driver_api/
  → middleware/ (freertos, rtos_api, fatfs, roboeffect wraps等)
  → app_framework/
  → app_src/
→ 链接 25 个预编译库 → 生成 Release/B6_Audio_SDK.adx (ELF)
→ post-build
  → objcopy 生成 output/B6_Audio_SDK.bin（纯代码 bin）和 flash_param.bin
  → script_post.bat: merge.exe 按 merge.ini 合并 6 个分区 → flash.img (4MB 整片镜像)
  → Andes_MVAGenerate.exe 打包 → main_merge.MVA / main_merge.MVA.bin
→ 自动生成分析文件: symbol.txt / readelf.txt / objdump.txt / .PHONY.size
```

**编译产物一览**（`Release/output/`）:

| 文件 | 大小 | 用途 |
|------|------|------|
| `main_merge.MVA.bin` | ~1.65 MB | **烧录文件**（含代码+参数+CRC，IAPBurner/升级使用） |
| `main_merge_0x8bcd.MVA` | ~1.65 MB | 同上，文件名带 CRC 后缀（后缀随固件内容变化） |
| `flash.img` / `flash.img.bin` | 4 MB | 整片 Flash 镜像（含全部分区，烧录器整片烧录用） |
| `B6_Audio_SDK.bin` | ~1.39 MB | 纯代码段 bin（合并工具输入，不直接烧录） |
| `symbol.txt` / `readelf.txt` / `objdump.txt` | - | 符号表/ELF信息/反汇编（调试用） |
| `.PHONY.size` | - | 段尺寸统计（text 1,441,946B / data 3,696B / bss 123,464B） |

> ELF 文件为 `Release/B6_Audio_SDK.adx`（含调试信息，供调试器使用）。

### 2.3 常见编译错误

| 错误现象 | 原因 | 解决方法 |
|----------|------|----------|
| 找不到头文件 | Include 路径配置错误 | 检查 `.cproject` 中的 Include 路径 |
| 库链接失败 | 库文件版本不匹配 | 检查 `makefile.defs` 中的库选择 |
| 宏未定义 | 全局宏未配置 | 检查工程属性中的 Compiler Symbols |
| Flash 空间不足 | 启用了过多功能 | 关闭不必要的 `CFG_FUNC_*` 宏 |

## 3. 固件烧录

### 3.1 烧录方法

**方法1：使用 IAPBurner（推荐）**
1. 连接烧录器到目标板
2. 运行 IAPBurner
3. 选择 `Release/output/main_merge.MVA.bin`
4. 点击烧录

**方法2：整片 Flash 镜像烧录（烧录器场景）**

使用烧录器烧录 `Release/output/flash.img`（4MB，含代码+音效参数+提示音+全部分区）。

> 注意：`tools/flash.bat` 并非烧录脚本，而是"重新合并固件"脚本（重新生成提示音并执行分区合并与 MVA 打包）；其内部还校验旧固件名 `BT_Audio_APP.bin`，属历史遗留，当前工程请勿依赖。

### 3.2 验证烧录

烧录完成后，连接 UART 调试串口（波特率默认 115200），上电后应看到启动日志：

```
FlashBoot start → CHIP_ID b6 → CRC校验 → 跳转用户代码
→ B62_Audio_SDK V0.3.16
→ Driver/OtgHost/BtLib 版本信息
→ Flash分区表 → Core2 init → 音频核心初始化
→ 蓝牙协议栈启动 → 模式初始化 → 进入工作模式
```

> 说明：工程根目录的 `log.txt` 是早期（2026-09-16）抓取的历史日志，其中包含 `AudioEffect_Parambin_Check failed!` 与 `mode init failure,enter safe mode` 错误（当时 audio_effect.bin 与固件不匹配所致）。2026-09-22 重新编译并烧录的新固件已确认正常启动，不再出现上述错误。

## 4. 基本配置

### 4.1 配置体系概览

SDK 通过宏定义实现功能裁剪，核心配置文件位于 `app_src/system_config/`：

| 配置文件 | 职责 | 修改频率 |
|----------|------|----------|
| `app_config.h` | 功能模式总开关 | 高（项目定制必改） |
| `chip_config.h` | 芯片型号/封装选择 | 低（项目初期定） |
| `bt_config.h` | 蓝牙名称/地址/协议 | 中 |
| `clock_config.h` | 时钟频率配置 | 低 |
| `gpio_config.h` | GPIO 引脚分配 | 高（硬件适配必改） |
| `flow_config.h` | 音效图 Source/Sink 定义 | 中 |
| `resource_defs.h` | Flash 地址/FIFO 大小 | 低 |

### 4.2 常用配置示例

**启用/禁用音频模式**（`app_config.h`）:

```c
#define CFG_APP_BT_MODE_EN          // 启用蓝牙播放模式
#define CFG_APP_LINEIN_MODE_EN      // 启用 LineIn 模式
//#define CFG_APP_USB_AUDIO_MODE_EN // 禁用 USB Audio 模式
```

**配置蓝牙名称**（`bt_config.h`）:

```c
#define CFG_BT_NAME    "MySpeaker"  // 蓝牙设备名称
#define CFG_BLE_NAME   "MySpeaker_BLE"  // BLE 设备名称
```

**配置 GPIO 引脚**（`gpio_config.h`）:

```c
#define CFG_UART_TX_PORT    GPIOA0  // UART TX 引脚
#define CFG_LED_PIN         GPIOA5  // LED 控制引脚
```

### 4.3 配置验证

修改配置后，重新编译并烧录，观察 UART 日志验证配置是否生效。

## 5. 启动流程

### 5.1 启动流程概览

```
上电复位
  ↓
FlashBoot（芯片内置引导）
  ├─ 校验用户代码 CRC
  └─ 跳转到用户代码
  ↓
main() 硬件初始化
  ├─ Chip_Init() / WDG0_Enable()
  ├─ DCDC/LDO 电压配置
  ├─ SystemClockInit()
  ├─ SpiFlashInit()
  ├─ LogUartConfig()
  ├─ flash_table_init()
  ├─ DualCore_ReleaseCore2ToRun()（双核）
  └─ sys_parameter_init()
  ↓
MainAppTaskStart()
  └─ xTaskCreate(MainAppTaskEntrance)
  ↓
vTaskStartScheduler()
  ↓
MainAppTaskEntrance()
  ├─ SystemInit()
  │   ├─ DMA通道分配
  │   ├─ TemperatureCorrInit()
  │   ├─ SysVarInit()
  │   ├─ AudioCoreServiceCreate()
  │   ├─ BtStackServiceStart()
  │   └─ DeviceServiceInit()
  │
  └─ while(1) 消息主循环
      ├─ MessageRecv()
      ├─ PublicMsgPross()
      ├─ DeviceServicePocess()
      └─ SysModeGenerate()
```

### 5.2 关键启动文件

| 文件 | 职责 |
|------|------|
| `app_src/startup/crt0.S` | C 运行时启动汇编（复位向量、栈初始化） |
| `app_src/main.c` | main() 函数，硬件初始化 |
| `app_src/main_task.c` | 主任务，系统初始化和消息循环 |

## 6. 调试方法

### 6.1 UART 日志

SDK 使用 `APP_DBG()` / `DBG()` 宏输出调试日志：

```c
APP_DBG("Driver Version: %s\n", GetLibVersionDriver());
DBG("Main task MSG_POWER\n");
```

**日志开关**（`app_config.h`）:
```c
#define CFG_UART_LOG_EN    // 启用 UART 日志
```

### 6.2 日志分析

启动日志中的关键信息：

| 日志内容 | 含义 |
|----------|------|
| `FlashBoot start` | FlashBoot 引导开始 |
| `CHIP_ID b6` | 芯片型号识别 |
| `Driver Version: 1.1.15` | 驱动库版本 |
| `flash table name is error!` | Flash 型号未识别（使用默认分区表，可忽略） |
| `AudioEffect_Parambin_Check failed!` | 音效参数校验失败（需用 ACPWorkbench 重新生成 audio_effect.bin 并重新合并固件）。注：此条出现在旧日志中，2026-09-22 新固件已正常 |
| `mode init failure,enter safe mode` | 模式初始化失败，进入安全模式（同上，为旧日志中的历史现象） |
| `bt device init success!` | 蓝牙初始化成功 |
| `CPU:14 M + 0 M Frame:0 M RAM:231 K` | CPU 占用率(Mcps)/帧率/RAM使用 |

### 6.3 在线调试

**USB HID 在线调音**（`app_config.h`）:
```c
#define CFG_FUNC_AUDIO_EFFECT_ONLINE_TUNING_EN  // 启用在线调音
#define CFG_COMMUNICATION_BY_HS_USB             // 使用 HS USB HID
```

**UART 在线调音**:
```c
#define CFG_COMMUNICATION_BY_UART               // 使用 UART 通信
```

## 7. 常见问题

### 7.1 编译问题

**Q: 编译时报错 "找不到 xxx.h"**
A: 检查 `.cproject` 中的 Include 路径，确认对应目录已添加。

**Q: 链接时报错 "undefined reference to xxx"**
A: 检查预编译库是否正确链接，确认 `makefile.defs` 中的库选择。

### 7.2 烧录问题

**Q: 烧录后无日志输出**
A: 检查 UART 连接、波特率配置（默认 115200）、GPIO 引脚配置。

**Q: 烧录后进入 Safe Mode**
A: 检查 `audio_effect.bin` 是否正确生成并合并到固件。

### 7.3 功能问题

**Q: 蓝牙无法连接**
A: 检查 `bt_config.h` 中的蓝牙名称/地址配置，确认蓝牙协议栈已启动。

**Q: 音频无声**
A: 检查 Source/Sink 通路配置、DAC 初始化、FIFO 分配。

## 4.4 DAC0 被 AudioCore 初始化的调用链 (【SDK】, 勿改)

headphone.c L203-205 注释所说"DAC0 already initialized by AudioCore"的实际来源:

```
模式启动(例: LineIn → linein_mode.c:220 LineInInit)
  → linein_mode.c:224 if(!ModeCommonInit())     每个模式Init都调用
  → mode_task_api.c:346 ModeCommonInit()         公共初始化
  → 构建AudioCore net + 填充 DacParamCtCommon(L481-492)
  → L493 若 DAC_SEL==DAC0_MODULE
  → L495 AudioDAC_Init(DAC0_MODULE, &DacParamCtCommon, ...)  ★DAC0初始化
  → L475 gCtrlVars.HwCt.DAC0Ct.Enable = 1        ★DAC0使能
```

| 环节 | 位置 |
|------|------|
| DAC_SEL=DAC0_MODULE | module_config.h L249-256【SDK】 |
| ModeCommonInit() 函数 | mode_task_api.c L346【SDK】 |
| DAC参数+Init | mode_task_api.c L481-504【SDK】 |
| DAC0 Enable=1 | mode_task_api.c L475【SDK】 |
| LineIn模式调用点 | linein_mode.c L224【SDK】 |
| BT模式调用点 | bt_play_mode.c L605【SDK】 |

**含义**: DAC0 在每次模式启动时由 AudioCore 初始化并 Enable=1, 音频流持续送进 DAC0 sink。因此耳机模块只负责"静音/放行输出级" (HpDacOutput), 不重复初始化 DAC0。


```
  │            L271 右声道8次平均采样      HpAdcSampleNormalized(AD0,PA30)
```

## 5.5 ADC 采样注意
- B6 SarADC 一个通道复用多个GPIO → 必须 init→delay→读→deinit (参考 adc_levels.c L97注释, 同机制)

- 判定: 16Ω≈0.16V(133mV), 32Ω≈0.32V(267mV), 阈值240mV

## 5.7 HeadphoneTaskPoll() 函数详细逻辑 (headphone.c L225-311)

**挂接方式**: 不是独立 RTOS 任务, 而是在 main_task.c L887 主循环 while(1) 内被直接调用,
随 MainApp 任务约每 10ms(MAIN_APP_MSG_TIMEOUT)执行一次。全逻辑跑在 OS 上下文(可安全 osTaskDelay)。

### 5.7.1 输入输出
- 输入: 无参数
- 输出: 更新 s_hpState(状态)/s_imp(阻抗), 控制 PB8/PB10/DAC0 静音, 打印日志
- 静态变量: s_hpDetRaw(上次原始电平), s_detectCnt(防抖计数), s_hpState(当前状态), s_usbHold(USB占用)

### 5.7.2 逻辑步骤 (逐行)

```
L227  raw = HpDetRead()                 读PB9, 返回 bool(低电平=插入=true)
── 防抖(软件消抖) ──
L230-238  若 raw==s_hpDetRaw → 计数++, 否则清零并更新 s_hpDetRaw
L239-242  若 连续计数 < HP_DEBOUNCE_COUNT(5) → return  (未稳定, 放弃本轮)
           平衡: 需连续5次(约50ms)读同电平才认, 滤除接触抖动
L244  newState = raw ? IN : NO          由此轮稳定电平推导新状态
? L246-310 若 newState != s_hpState (状态发生变化) ?
│ L248  更新 s_hpState = newState
│ ┌─────────────────── 分支1: 插入 (L250-303) ───────────────────┐
│ │ L252  打印 [HP] Plug insert                                   │
│ │ L255  若 !s_usbHold (USB未占用才处理)                          │
│ │ L264  osTaskDelay(100ms)   机械稳定: 慢插触点完全贴合         │
│ │ L266-287  for retry=0..1 (至多重试1次)                        │
│ │    L268 HpAdEnSet(true)    AD_EN(PB8)↑ 开3.3V参考             │
│ │    L269 osTaskDelay(50ms)  参考电压稳定                      │
│ │    L270 rAdc=采样(右,AD0,PA30)  8次去极值平均                 │
│ │    L271 lAdc=采样(左,AD1,PA31)                                │
│ │    L272 HpAdEnSet(false)   AD_EN↓ 关参考(消除电流底噪)        │
│ │    L274  右电压 = rAdc*3300/4096                              │
│ │    L275  左电压 = lAdc*3300/4096                              │
│ │    L277-285 校验 L/R 对称: |L-R|>300mV 且首轮 →              │
│ │              打印 asym + 延时100ms + continue 重采            │
│ │    L286  break (对称或第2轮即采用当次值)                      │
│ │ L289-290  判阻抗 mv<240→16Ω, 否则32Ω                         │
│ │ L292-297  存档 s_imp(左右ADC/电压/阻抗)                      │
│ │ L299-300  打印 [HP] Impedance: L=x R=x (AD L=x R=x)           │
│ │ L302  HpDacOutput(true)  HP_EN↑ + DAC0解除静音 → 耳机出声     │
│ └───────────────────────────────────────────────────────────────┘
│ ┌─────────────────── 分支2: 拔出 (L305-309) ────────────────────┐
│ │ L307  打印 [HP] Plug remove (DAC0 muted)                      │
│ │ L308  HpDacOutput(false) HP_EN↓ + DAC0静音 → 耳机无声         │
│ └───────────────────────────────────────────────────────────────┘
└──────────────────────────────────────────────────────────────────
```

### 5.7.3 关键设计要点
1. **防抖**: 连续5次同电平(50ms)才生效, 且防抖计数在状态没变时不重置——保证插稳才采。
2. **只采样一次**: 插入后仅当次采样, 不周期重采(避免反复开关AD_EN产生底噪+省时)。
3. **AD_EN 短开即关**: 参考电压只在采样窗口(~500ms)开启, 平时关闭→消除了持续电流底噪。
4. **重试机制**: 慢插时若 L/R 电压相差>300mV(触点未完全贴合)则重采一次。
5. **USB 互斥**: s_usbHold 置位时(HeadphoneSetOutput(false)由USB在线调音调用)不执行插入动作。
6. **拨出即时静音**: 无采样过程, 直接关耳放+静音。

### 5.7.4 状态变量说明
| 变量 | 类型 | 说明 |
|------|------|------|
| s_hpDetRaw | bool | 上次读到的 PB9 电平(低=插入) |
| s_detectCnt | uint8 | 当前连续相同电平计数(防抖) |
| s_hpState | HP_STATE_E | 当前耳机状态(NO/IN) |
| s_usbHold | bool | USB/在线调音占用标志(置true强制静音) |
| s_imp | HP_IMPEDANCE_INFO | 阻抗结果结构体(左右ADC/电压/判定) |

### 5.7.5 时序估算
插入到出声总耗时: 50ms防抖 + 100ms机械 + 50ms参考稳定 + (8次×30ms)×2声道 + 可能重试100ms ≈ 0.7~1.2s
拔出到静音: 50ms防抖(立即静音, 无采样) → 约50ms

# 七、USB 固件升级 (FS-USB 双区) —【SDK自带 vs 自研区分】

> 重要提醒: 升级流程中**绝大多数的防变砖/双区逻辑是 SDK/ROM 自带**, 我们**没有修改**。交接时请勿改动标注【SDK】的部分, 否则可能破坏防变砖。

## 7.1 总览: 哪些是 SDK 自带, 哪些是我们改的

| 环节 | 归属 | 位置 | 说明 |
|------|------|------|------|
| 预编译引导(bootloader) | 【SDK】 | middleware/flashboot/flash_boot.c (flash_data[0x10000] 二进制) | 不可改源码, 升级核心落盘/CRC 在其中 |
| ROM 双区落盘 API | 【SDK】 | driver/driver/inc/rom.h (ROM_BankBUpgradeApply/ROM_CRC16) | ROM 固化, 仅声明, 调用在 flashboot |
| 升级状态寄存器 SREG_BOOT_REGISTER | 【SDK】 | app_src/components/upgrade/upgrade.h L118-125 | 0x40052028 bitband, ROM 特性(掉电丢失) |
| 通道宏 CHN_MASK_* | 【SDK】 | upgrade.h L104-116 | CHN_MASK_USBCDC_FS=(1<<9)=0x200(L114) |
| start_up_grate() 触发入口 | 【SDK】 | upgrade.c L42-119 | 写通道→置STATE_UPGRADE_APPLY→复位 |
| report_up_grate() 结果上报 | 【SDK】 | upgrade.c L7-40 | 读状态→打印升级OK/失败 |
| **强制 FS 端口(OTG_DEVICE_PORT_FS)** | **【改】** | app_config.h L712 | 新增强制定义(硬件FS接线A8/A9) |
| **关 HS HID(CFG_COMMUNICATION_BY_HS_USB 注释)** | **【改】** | app_config.h L159 | 我们注释的(原定义) |
| FS-USB 描述符/检测 | 【SDK】 | app_src/components/otg/... | SDK 原生 |

**结论: 我们只改了 app_config.h 两个宏(关HS + 强制FS), 其余升级机制全为SDK自带, 未改动。**

## 7.2 升级流程 (3次复位, 全【SDK】)
```
复位1: 正常启动, FlashbootState=0
PC(IAPBurner)发起
→ start_up_grate() [upgrade.c L42] 匹配通道 [L85-86 CHN_MASK_USBCDC_FS]
→ 写 SREG BootReg [L113 STATE_UPGRADE_APPLY] → Reset_McuSystem [L116]
复位2: FlashbootState=0x4(Apply)
  flashboot(预编译) 执行:
    "start upgrade" / "PC IS OK" / OtaRecvFrame / mva_command_handle / mva_code_handle
    MvaPackageGet 逐段接收 → MVA MAGIC/CAPACITY/ChipID 校验
    boot crc / code crc / 每段 crc 全部一致 → 写入B区(不动A区)
复位3: FlashbootState=0x6(Done)
  B区生效 → report_up_grate [upgrade.c L7] 读状态
  → "升级OK" 打印 + SoftFlagUpgradeOK 注册 [L30-33]
```

## 7.3 防变砖原理 (全【SDK】, 勿改)
- 新固件写 **B区**, A区老固件始终保留 → 掉电/写坏不影响A区。
- SREG_BOOT_REGISTER(0x40052028)**掉电丢失**(ROM特性, rom.h 注释) → 掉电后 flashboot 不记得有升级 → 校验A区现任固件照常启动。
- ROM 双区落盘有 A/B CRC 校验(errno: ERRNO_BANKA_CRC_ERR 等, rom.h L50), 失败自动回退A区。
- **结论: 变砖风险极低(老固件全程不被触碰), 也正因如此这些SDK机制不能乱动。**

## 7.4 我们真正做的改动 (仅配置)
| 文件 | 行号 | 改动 | 原因 |
|------|------|------|------|
| app_config.h L159 | 【改】 | `//#define CFG_COMMUNICATION_BY_HS_USB` 注释 | 关闭HS HID, 避免双HID干扰 |
| app_config.h L712 | 【改】 | `#define OTG_DEVICE_PORT_FS` | 硬件FS在A8/A9, 强制FS枚举 |

> 曾尝试过但在调试中**已回退**的改动(记录, 勿重复):
> - main.c 冷启动加 OTG_FS_DeviceInit (会误锁FS检测状态, 已删)
> - mv_upgrade 自动复位注释松开 (与IAPBurner流程无关, 保持注释)

## 7.5 硬件根因 (已解决)
- 现象: 插USB无枚举迹象/无日志。
- 根因: USB连接器 GND 误接3.3V。重接GND后 FS-USB 正常枚举。
- 教训: 排查USB枚举先查 VCC/GND/DP/DM 接线, 勿先改SDK宏。

# 九、提示音播放逻辑与关闭方法

## 9.1 提示音总开关
`CFG_FUNC_REMIND_SOUND_EN` (app_config.h L91) — 定义=提示音功能使能。

## 9.4 关闭方法

### 方法A(推荐): 关闭总开关
将 app_config.h L91 注释:
```c
// #define CFG_FUNC_REMIND_SOUND_EN
```
效果: 所有提示音关闭, 编译体积减小。副作用说明:
- remind_sound.c/h 仍编译但不被调用(初始化/请求宏被 #ifdef 屏蔽)
- 个别代码可能有 `#ifdef CFG_FUNC_REMIND_SOUND_EN` 分支, 关闭后走 else(通常无害)

### 方法B: 保留功能但静音
不改宏, 把 CFG_PARAM_FIXED_REMIND_VOL 设为 0 (app_config.h L428):
```c
#define CFG_PARAM_FIXED_REMIND_VOL   0   // 0=提示音用 music vol 同音量且不提示
```
注意: 注释说明 "0 表示跟 music vol 同音量", 并非静音。若想"保留功能但听不到", 建议：
- 方案B1: 关闭宏(方法A)
- 方案B2: 逐个删/注释各 mode 的 RemindSoundServiceItemRequest 调用(见9.3表)

## 9.5 说明
- 提示音素材(xianlumo、shengkam等)来自 flash 中的 const data/录音区, 由 tools/script 预生成。
- 无需提示音时, **推荐方法A(注释 CFG_FUNC_REMIND_SOUND_EN)**, 一处解决, 不再需要逐点删调用。

> 如果需要该功能，按这个改即可：恢复 app_config.h L91 的 `#define CFG_FUNC_REMIND_SOUND_EN` 定义, 即恢复全部提示音(开机/连接/模式切换等)。

# 十、OXS控制与GC1808采集通路

## 10.1 主要入口

| 功能 | 文件/入口 |
|---|---|
| OXS UART1初始化 | `components/headphone/headphone.c` / `OxsProtocolInit()` |
| OXS主任务解析 | `OxsProtocolPoll()`，由 `MainAppTaskEntrance()` 周期调用 |
| UART1接收 | `UART_Interrupt()`（双核）或 `UART1_Interrupt()`（单核），只写环形缓冲 |
| 耳机插拔上报 | `HeadphoneTaskPoll()` 去抖和阻抗识别完成后发送 |
| 输出状态应用 | `OxsOutputControlRefresh()` |
| 断点状态 | `BP_SYS_INFO.Oxs*`，2秒合并保存 |
| GC1808采集 | `app_mode_linein/linein_mode.c` 的 `CFG_LINEIN_INPUT_SOURCE` 分支 |
| USB-HID日志 | `startup/retarget.c` + `otg_device_custom_hid_request.c` |

## 10.2 编译开关

```c
#define LINEIN_INPUT_INTERNAL_ADC       0
#define LINEIN_INPUT_GC1808_I2S2       1
#define CFG_LINEIN_INPUT_SOURCE         LINEIN_INPUT_GC1808_I2S2
```

默认为GC1808。可在工程Compiler Symbols中预定义 `CFG_LINEIN_INPUT_SOURCE=0`，或修改默认宏，编译原内部ADC通路。

## 10.3 GC1808时序和数据格式

```text
DSP PA20 MCLK1_OUT 12.288 MHz -> GC1808 SCKI
GC1808 BCK  3.072 MHz         -> DSP PA16 I2S2_BCLK
GC1808 LRCK 48 kHz            -> DSP PA17 I2S2_LRCLK
GC1808 DOUT, I2S 24-bit       -> DSP PA18 I2S2_DIN0
```

GC1808硬件绑带为MD0=1、MD1=1、FMT=0；每帧64 BCK。DSP内部PCM使用低24位有效对齐。MCLK启动后延时100 ms再开I2S2 RX，且外置ADC分支不关闭MCLK。

## 10.4 OXS协议要点

- 最大整包64字节，帧头线上字节 `4F 52 45 50`，帧尾 `5A 5A`。
- CRC为CRC-16/IBM/ARC：初值0、反射多项式0xA001、异或输0、CRC低字节先发。
- 帧结构错误静默丢弃；语义错误始终回错误ACK；成功时仅在请求Ack非0时返回对应数据包。
- 主动耳机事件Packet ID从1递增，溢出后跳过0。

## 10.5 USB-HID日志接口

- PA8/PA9的FS USB只枚举HID，不启用USB声卡应用模式，连接电脑不会离开LineIn。
- HID接口0保留原在线调音、升级触发及256字节控制 `GetReport` 日志包：`A5 5A 30 01 + 最多252字节日志`。
- HID接口1为通用工具新增中断IN日志端点EP5 IN。报告长度64字节：`A5 5A 30 01 + 最多60字节日志`，不足部分补0。
- `UsbHidLogPoll()`由主任务周期调用；仅FIFO有数据且USB硬件已初始化时尝试发送，端点未就绪或主机未读取时不推进FIFO，日志写满后丢弃新数据而不阻塞音频任务。
